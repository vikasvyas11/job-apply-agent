How it works

What happens between pasting a link and opening the finished Google Doc, and the checks that keep a small local model honest. Updated 20 November 2026.

The pipeline for one job

  1. Read the job. The page is fetched and cleaned with requests and trafilatura. If it turns out to be a JavaScript-only page or a bot check, a headless Chromium (Playwright) renders it and the text is extracted again. If that fails too, the pasted description is used.
  2. Name it. A short model call pulls out the company and job title, used to name the document. Your company override wins if you gave one.
  3. Research the company. A few DuckDuckGo searches find the company's own pages and recent news. Each passage is capped in length so the prompt stays within the model's context. If search fails, the job carries on without it.
  4. Write the CV. The prompt combines the flow's resume instructions, its writing style, the job description, the research, the flow's master CV (with the region's city and phone filled in) and the flow's project notes.
  5. Write the cover letter. A second, separate prompt uses the tailored CV, the flow's reference letter and project notes. It is told not to include your location or phone.
  6. Fill the document. The template is copied in Google Drive, and the CV and Cover Letter tabs are rewritten with real formatting.

Why the flows can't mix

Every run carries one profile: a flow and a region. The profile decides which folder the content comes from (content/data/, content/growth/ or content/software/). Nothing reads content any other way, so a Software Dev run has no route to the Growth CV, notes, reference letter or prompts. An automated test builds both prompts for each flow and checks that no other flow's material appears in them.

Regions

Each master CV's contact line contains {{LOCATION}} and {{PHONE}}. The chosen region's values replace them before the model sees the CV, and again when the real contact header is restored after generation. If a value is empty, the placeholder and its separator are removed rather than left as a gap.

Checks around the model

Problem seen in practiceWhat the agent does
Long prompts silently truncated, giving near-empty outputThe context window is sized to each prompt, and output that is too short is retried once at the maximum size, then rejected.
The model invented a phone number or cityEverything above PROFESSIONAL SUMMARY is replaced with the real contact header in code.
The model invented an entry (a made-up “v1” of a real project) or promoted background notes into a new oneEvery job, project and education entry in the tailored CV must match an entry in that flow's master CV by title or organisation; anything else is removed with its bullets. Both prompts also tell the model never to upgrade your role (“supported” stays supported).
Entry titles written in capitalsEach title is given the casing your master CV uses (“University College London”, “AI”, “v2”).
A cover letter appeared inside the CV, or CV sections inside the letterEach output is scanned for the other document's markers and regenerated.
AI clichés in lettersA draft containing a banned phrase gets one more attempt; the cleaner draft is kept.
Google login expired mid-batchBackground runs never open a sign-in window. They stop with a message telling you to reconnect on the Setup page.
Browser tab closed or asleepWork runs on a background thread and each result is saved to disk as it finishes.

Document formatting

The model writes the CV in a simple convention: ALL-CAPS headings, **Title** | Organisation | Dates for entries, * for bullets and a Tools/Skills: line. A formatter turns that into Google Docs formatting:

  • Blank lines are dropped. All vertical spacing comes from paragraph styles, so gaps are identical however the model laid out its text.
  • Every paragraph gets single line spacing and explicit space above and below: most above a section heading, less above each entry, none between bullets.
  • Entry titles and the Tools/Skills: label are bold; links stay clickable; bullets use tighter indents than Google's default.
  • The cover letter gets one style over the whole tab: 11 pt text, 1.15 line spacing, with paragraphs separated by blank lines.

Privacy

Your CVs, notes, settings, Google files and generated runs stay on your computer and are excluded from version control. The model runs locally. The only network calls are fetching the job page, the company searches and writing to your own Google Drive. The web interface listens on 127.0.0.1 only, and Streamlit's usage statistics are switched off.
