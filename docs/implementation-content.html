Key decisions

  • Isolation by construction. Flows are folders, and a run holds one Profile that every content read goes through. There is no shared CV to filter, so there is nothing to leak.
  • Regions as data, not code. City and phone live in local_settings.json; the CVs carry {{LOCATION}} and {{PHONE}}. The code holds no personal details.
  • Spacing from styles only. Blank lines in model output are dropped and every paragraph gets explicit spacing and single line spacing, so the template's defaults can't make gaps uneven.
  • No browser prompts from background work. A batch asks Google for credentials non-interactively and fails with a clear message; only the Setup page may open a sign-in window.

Status and evidence — 20 November 2026

Checked on 20 November 2026 on a Windows laptop (CPU only), with the local model qwen3.5:latest.

  • Automated tests: 123 pass (pytest), ruff check is clean, and npm run docs:test passes for this documentation.
  • Interface, in a real browser: choosing Software Dev and India reached the batch runner unchanged, the run recorded and displayed that profile, and the page refreshed itself until the batch finished. On Setup, saving the Growth CV changed only the Growth file, and saving a region's phone number updated the settings.
  • Real generation, two full rounds: one job per flow (Data Science with UK, Growth with India, Software Dev with UK), CV and cover letter each, about 4 to 7 minutes per document. In both rounds every CV used the right region's city and phone, kept the master CV's sections in order with no Additional Experience section, contained none of another flow's talking points and no mention of SAIL; every letter opened with "Dear Hiring Manager,", signed off with "Best," and the applicant's first name, had no location or phone, no em dashes and no banned phrases.
  • What the first round caught: the model invented an entry (a "v1" of a real project), pulled a project from background notes into the wrong flow, wrote titles in capitals, upgraded "supported" to "led", and confused Fastify with FastAPI. The entry check, title casing, accuracy rules and a clarified project note were added; the second round showed none of these. In one second-round CV the model dropped every bullet marker; plain lines under an entry are now treated as bullets.
  • Layout: the formatter's output for each second-round CV was rendered at A4 width with the same sizes and spacing: 1.2 to 1.5 pages, with even gaps.

Not yet done or verified: writing to Google Docs in this round. The saved Google login had expired (Google's 7-day limit for apps in Testing), and only its owner can sign in again. The model can still round a figure (one CV wrote 15% for 15-20%), so every document needs reading before it is sent.
